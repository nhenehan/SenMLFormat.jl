Formats

Each format is a module with the same shape: decode and encode for whole packs (both validate; the _unchecked versions don't), RecordReader to read record by record, and StreamEncoder to write record by record. JSON and CBOR also have a StreamDecoder that takes bytes as they arrive.

By media type

SenMLFormat.decode — Function
decode(media::MediaType, input) -> Pack

Reads and checks a pack of the given media type. input is bytes or a string. The SenSML types also accept streams; for CBOR that means an indefinite-length array. For EXI, the header must carry its options (RFC 8428 section 8); use SenMLFormat.Exi.decode with out_of_band for streams without them.

pack = SenMLFormat.decode(SENML_CBOR, bytes)
source
SenMLFormat.encode — Function
encode(media::MediaType, pack) -> Vector{UInt8}

Checks a pack and writes it in the given media type. SenSML CBOR uses an indefinite-length array; the other SenSML types are written the same as SenML. EXI is bit-packed with no cookie; SenMLFormat.Exi.encode has the other choices.

source
SenMLFormat.encode_unchecked — Function
encode_unchecked(media::MediaType, pack) -> Vector{UInt8}

encode without checking the pack first, for packs that are already valid (decoded, or built by trusted code). Values a format cannot write are still refused.

source

JSON

SenMLFormat.Json — Module
SenMLFormat.Json

The JSON format of SenML (RFC 8428 section 5): media types application/senml+json and, for streams, application/sensml+json.

The first example of RFC 8428 section 5.1.2:

pack = SenMLFormat.Json.decode("""[{"bn":"urn:dev:ow:10e2073a01080063:","n":"voltage","u":"V","v":120.1},
                               {"n":"current","u":"A","v":1.2}]""")
SenMLFormat.Json.encode(pack)  # the same JSON, without whitespace

Reading checks the JSON grammar, label types, repeated labels, at most one value per record, and labels ending in _. decode then validates the pack. Unknown labels with string, number or boolean values are kept as Extensions; other unknown labels are skipped.

source

decode(input) -> Pack

Reads a complete SenML JSON pack (bytes or a string) and validates it (RFC 8428 section 4). Throws a SenMLError.

source
SenMLFormat.Json.decode_unchecked — Function
decode_unchecked(input) -> Pack

Reads a complete SenML JSON pack (bytes or a string), checking only the JSON form: grammar, label types, repeated labels, at most one value, labels ending in _. Use validate for the rules of section 4.

source
SenMLFormat.Json.encode — Function
encode(pack) -> Vector{UInt8}

Validates a pack (RFC 8428 section 4) and writes it as SenML JSON.

source
SenMLFormat.Json.encode_unchecked — Function
encode_unchecked(pack) -> Vector{UInt8}

Writes a pack as it is, without validating. Infinite and NaN numbers are still refused, because JSON has no way to write them.

source
SenMLFormat.Json.encode_record — Function
encode_record(io, record, index)

Writes one record object (for writing a SenSML stream one piece at a time; see StreamEncoder). index (1-based) is only used in error reports.

source
SenMLFormat.Json.RecordReader — Type
RecordReader(input)

Reads the records of a complete SenML JSON pack one at a time, without collecting them. Records are checked as they are read (JSON form only); feed them to a Validator for the rules of section 4. Iterate it, or call next_record! until it returns nothing, then finish.

source
SenMLFormat.Json.StreamEncoder — Type
StreamEncoder()

Writes a SenSML JSON stream one piece at a time: record! writes [ before the first record and , before the others; finish! writes ] (or [] if no record was written). It does not validate; run a Validator next to it if needed.

source
SenMLFormat.Json.StreamDecoder — Type
StreamDecoder()
StreamDecoder(; registered_units = false)

Decodes a SenSML JSON stream (section 4.8) as its bytes arrive. push! bytes, then call next_record! until it returns nothing; each record is ready (and validated) as soon as its closing brace has arrived. isfinished tells whether the closing ] was read; finish ends the stream.

source

CBOR

SenMLFormat.Cbor — Module
SenMLFormat.Cbor

The CBOR format of SenML (RFC 8428 section 6): media types application/senml+cbor and, for streams, application/sensml+cbor. CBOR itself is RFC 8949.

The example of RFC 8428 section 5.1.1:

pack = Pack([Record(n = "urn:dev:ow:10e2073a01080063", u = "Cel", v = 23.1)])
bytes = SenMLFormat.Cbor.encode(pack)
SenMLFormat.Cbor.decode(bytes) == pack

Reading:

  • Registered labels are the integer keys of Table 4. A text key that spells a registered label ("v") is not that label in CBOR, so it is an unknown field and is ignored (section 4.4); its value is skipped, not kept, so a translation to JSON cannot write the label twice. Unknown integer keys are ignored. Unknown text keys are extensions (kept when their value is a scalar), and fail when they end in _.
  • Numbers may be integers, half/single/double floats, or decimal fractions (tag 4). bver may only be an unsigned integer. Text and byte strings must have a definite length.
  • A SenML pack is a definite-length array. A SenSML stream may also be an indefinite-length one (decode_sensml).

Writing puts every number in the smallest form that reads back as the same double (an integer when it is a whole number, else a half, single or double float), the integer keys in the order of the RFC's examples, then extensions under text keys. This writes the RFC's section 6 example byte for byte.

source

XML

SenMLFormat.Xml — Module
SenMLFormat.Xml

The XML format of SenML (RFC 8428 section 7): media types application/senml+xml and application/sensml+xml.

The document is a sensml element in the namespace urn:ietf:params:xml:ns:senml, holding one senml element per record. Their attributes without a prefix are the fields (Table 5).

Reading:

  • Only UTF-8 is accepted (section 7). A DTD is refused (so no entity expansion).
  • Whitespace, comments and processing instructions may appear between records. Other text and child elements may not.
  • Attributes in other namespaces (xml:lang, xmlns:*, foreign ones) are ignored. Unknown attributes without a prefix are extensions (string values).
  • INF, -INF and NaN are valid xs:double values but not SenML numbers.

Writing gives <sensml xmlns="urn:ietf:params:xml:ns:senml"> with one empty <senml .../> element per record, attributes in the order of the RFC's examples, no XML declaration and no whitespace.

SenMLFormat.Xml.RecordReader — Type
RecordReader(input)

Reads the records of a SenML XML document (bytes or a string) one at a time. Throws a SenMLError if the input is not UTF-8. Call next_record! until it returns nothing, then finish; or iterate it.

Records have no child elements, so namespaces only need two levels: the root's declarations (kept here) and each senml element's own.

source

Writes a SenSML XML document one piece at a time: the sensml start tag before the first record (record!), one senml element per record, and the end tag (finish!). It does not validate.

EXI

SenMLFormat.Exi — Module
SenMLFormat.Exi

The EXI format of SenML (RFC 8428 section 8): media types application/senml-exi and application/sensml-exi. Strict schema-informed EXI with the RFC's schema, through EXIFormat.

bytes = SenMLFormat.Exi.encode(pack)                              # bit-packed
bytes = SenMLFormat.Exi.encode(pack; alignment = :byte_aligned)   # byte-aligned
SenMLFormat.Exi.decode(bytes)
  • The header carries the EXI options with schemaId "a" (section 8); a stream that names another schema (or none) is refused with a :SchemaId error. A stream without options is read only when the caller gives them (out_of_band).
  • Strict EXI cannot carry extensions: they are dropped (section 8: "any extensions will be lost"), or refused with extensions = :error.
  • EXI cannot carry -0.0: an EXI Float's mantissa is an EXI Integer, which codes a negative number as its magnitude minus one (EXI 7.1.5), so there is no negative zero. -0.0 is written as 0.
  • No $EXI cookie by default (section 8 says SHOULD NOT over CoAP or HTTP).

The bytes equal rsenml's and EXIficient's for every test case.

source
SenMLFormat.Exi.decode — Function
decode(bytes; out_of_band = nothing) -> Pack

Reads a SenML EXI stream and validates the pack. The header must carry options with schemaId "a", unless out_of_band gives the alignment of a stream without options. Throws a SenMLError.

source
SenMLFormat.Exi.decode_unchecked — Function
decode_unchecked(bytes; out_of_band = nothing) -> Pack

Reads a SenML EXI stream without the rules of section 4.

source
SenMLFormat.Exi.encode — Function
encode(pack; alignment = :bit_packed, cookie = false, extensions = :drop) -> Vector{UInt8}

Validates a pack and writes it as SenML EXI: strict, with the options and schemaId "a" in the header. alignment is :bit_packed (the default) or :byte_aligned; cookie writes the $EXI cookie; extensions = :error refuses a pack with extensions instead of dropping them.

source
SenMLFormat.Exi.encode_unchecked — Function
encode_unchecked(pack; alignment = :bit_packed, cookie = false, extensions = :drop) -> Vector{UInt8}

Writes a pack as it is, without validating (values EXI cannot carry are still refused).

source
SenMLFormat.Exi.RecordReader — Type
RecordReader(bytes; out_of_band = nothing)

Reads the records of a SenML EXI stream one at a time: next_record! until it returns nothing, then finish. out_of_band gives the alignment (:bit_packed or :byte_aligned) of a stream whose header carries no options; such a stream is refused (:SchemaId) without it.

source
SenMLFormat.Exi.StreamEncoder — Type
StreamEncoder(; alignment = :bit_packed, cookie = false, extensions = :drop)

Writes a SenSML EXI stream record by record: record! each record, then finish! for the bytes. It does not validate. alignment is :bit_packed (the smallest) or :byte_aligned; cookie writes the $EXI cookie; extensions is :drop or :error.

source
SenMLFormat.EXI_SCHEMA_ID — Constant

The EXI schemaId of the RFC 8428 schema. The EXI header options must carry it (RFC 8428 section 8).

source
