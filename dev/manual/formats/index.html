Choosing a format

In this chapter you'll write the same pack in every SenML media type and compare their sizes.

pack = Pack([
    Record(bn = "urn:dev:mac:0024befffe804ff1:", bt = 1_700_000_000, bu = "Cel",
           n = "room", v = 21.5),
    Record(n = "setpoint", v = 21.0),
    Record(n = "heating", u = "/", v = 0.4),
])

for media in instances(MediaType)
    bytes = SenMLFormat.encode(media, pack)
    @assert SenMLFormat.decode(media, bytes) == pack
    @printf("%-28s CoAP %3d: %3d bytes\n", content_type(media),
            coap_content_format(media), length(bytes))
end

# EXI is bit-packed by default. Byte-aligned EXI is a little bigger, but every
# value starts on a byte boundary.
aligned = SenMLFormat.Exi.encode(pack; alignment = :byte_aligned)
println("EXI byte-aligned: ", length(aligned), " bytes")

# A content type from an HTTP header or a CoAP option picks the format.
println(media_type("application/senml+cbor"))
application/senml+json       CoAP 110: 143 bytes
application/sensml+json      CoAP 111: 143 bytes
application/senml+cbor       CoAP 112:  91 bytes
application/sensml+cbor      CoAP 113:  92 bytes
application/senml+xml        CoAP 310: 202 bytes
application/sensml+xml       CoAP 311: 202 bytes
application/senml-exi        CoAP 114:  79 bytes
application/sensml-exi       CoAP 115:  79 bytes
EXI byte-aligned: 98 bytes
SENML_CBOR

SenMLFormat.encode and SenMLFormat.decode take a MediaType, so a server can pick the format from a request's Content-Type header or CoAP Content-Format option. media_type turns either into a MediaType, and returns nothing for one it doesn't know.

Which one to use

FormatGood for
JSONWeb APIs and people reading logs. Every language can read it.
CBORSmall devices and CoAP: compact, and simple to write.
XMLSystems that already speak XML.
EXIThe smallest messages, for networks where every byte counts.

The SenSML media types mark the data as a stream. The bytes are the same as SenML, except in CBOR, where SenSML uses an array with no length up front (one byte more here), so the writer doesn't need to know how many records are coming.

EXI options

SenML EXI is strict, schema-informed EXI with the schema of RFC 8428 section 8. SenMLFormat writes the header with its options (schema ID "a"), as the RFC asks, so any EXI reader with that schema can read it. Keywords of SenMLFormat.Exi.encode:

  • alignment = :bit_packed (the default) is the smallest; :byte_aligned puts every value on a byte boundary, so a simple sensor can fill in a template by hand, as the RFC's second section 8 example shows.
  • cookie = true writes the $EXI cookie (the RFC advises against it over CoAP and HTTP).
  • extensions = :drop (the default) leaves out extensions, which strict EXI has no place for; :error refuses a pack that has any.

SenMLFormat.Exi.decode takes out_of_band for streams whose header leaves the options out.
